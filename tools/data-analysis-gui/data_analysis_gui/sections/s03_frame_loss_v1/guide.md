# S03 · 丢包率分析

**一句话总结：**综合接收连续性、FPGA 时钟推断缺帧、相对投递延迟及 trial 暴露，评价传输状态并明确无法判断的部分。

本节回答：**神经数据帧是怎么到达电脑的？采集端有没有丢帧、丢了多少、丢在哪里？主机时间戳相对采集时钟有多大的投递延迟？丢包有没有落进 trial 的分析窗口？**
数据：spike_counts_metadata 的每一帧（window_index、start_timestamp、end_timestamp、raw_total_count，以及 10-28 之后才有的第 5 个通道
device_timestamp_100us = FPGA 采集时钟）和原始 LSL 接收时间戳（不做时钟同步、不去抖）。除 trial 影响面板外，使用**全部收到的帧**，不按 trial 或通道筛选。
本版本把 neural_behavior `data_qc_v1` 的全部时序 / 丢帧图按原算法移植过来（frame_interval_hist、fpga_frame_drop、timestamp_vs_t_fpga、
relative_delivery_delay、relative_delivery_delay_timecourse、timestamp_vs_counter），并保留「按时间段 / 每 trial 的丢包影响」。
三个前提：
- window_index 每帧都 +1，**不能证明没有丢帧**（FPGA 时钟显示丢帧时 index 照样 +1）。
- start_timestamp 是主机生成的（= LSL 接收时间 − 20 ms，误差约 1 µs），所以接收间隔是传输抖动，不是采集时序。
- FPGA 时钟名义单位 100 µs，实测为 **1 ms**；采集帧周期实测 **19.2 ms**（不是名义的 20 ms）。

主要结果依次为 **传输状态总览 → 相对投递延迟 → 按时间和 trial 的影响**。没有 FPGA 时钟时不生成相对延迟页；Supplementary 补充页用于逐个查看采集缺口。

### 本节解决的问题与首页选图依据

本节依次检查五个问题：**收到的数据是否连续、独立采集时钟是否提示缺帧、异常发生在何时、数据是否出现额外投递延迟、异常是否触及任务分析窗口**。接收间隔、时钟缺失和投递延迟来自不同证据，不能合并为同一种“丢包率”；本节也不能仅凭时钟缺口定位丢失发生在采集、缓存或传输的哪个环节。

首页左栏用统一的主机时间轴对照接收间隔、FPGA 步长及分时汇总，右栏查看两种间隔的分布及主机与 FPGA 的时钟对照。

首页用于快速判断传输状态，未把所有细节挤在一起。**第二组相对投递延迟**专门检查额外等待的分布与趋势，它需要独立时钟及拟合前提；**第三组时间与 trial 影响**检查异常是否进入 Topbar 分析窗口，连接传输检查与后续神经分析。补充页保留逐缺口放大，用于核查首页异常的来源和算法前提。


阅读约定：以下按 subplot 的位置/标题逐项说明；重复的方向、电极、decoder 或记录面板逐个适用对应条目，双轴/色条与主面板合并解释。质量标准区分配置阈值、统计证据与描述性限制，历史数值不作为通用合格线。

## 图 1：Transmission overview

### 计算公式
**符号**
- t：从第一帧起算的主机 LSL 时间；Δ：相邻帧的接收间隔。
- θ：接收缺口阈值，默认 150 ms；T：FPGA 帧周期 19.2 ms；W：时间分箱长度，默认 1 分钟。

**步骤**
1. 左栏 A 和 B 在每个间隔的第一帧位置分别画出 Δ 和 FPGA 时间差。A 保留所有超过 θ 的间隔，B 显示所有正 FPGA 步长，判定线为 1.5T。
2. 左栏 C 将整个事件计入开始时所在时间段。绿线为长接收间隔总时长除以观测时长，红线为推断缺帧数除以收到帧数加推断缺帧数。阴影标记不足一个完整时间段的末段。
3. 右栏 D 和 E 分别统计接收间隔与 FPGA 步长的分布。E 将超过 100 ms 的步长画在独立小图中。
4. 右栏 F 展示主机时间与 FPGA 采集时钟的拟合关系，内嵌 50 帧局部放大图，标出缺口宽度与推断缺帧数。

### 结果解读
- **A 接收间隔**：绿点定位长接收间隔，与 C 绿线对应。
- **B FPGA 步长**：红点定位推断缺帧的步长，与 C 红线对应。
- **C 分时汇总**：查看哪段时间长接收间隔或推断缺帧最集中。左上角显示整场指标，长间隔占比以首帧至末帧的接收时长为分母，FPGA 缺帧率以匹配到 FPGA 时钟的接收帧数加推断缺帧数为分母。
- **D 接收间隔分布**：查看接收节律和长尾。
- **E FPGA 步长分布**：查看正常周期、跨周期步长以及整段记录的缺帧统计。
- **F 主机与 FPGA 时钟**：查看整段时钟关系和局部接收节律。

### 质量评价标准
- **A 接收间隔**：普通点会抽样，超阈值点全部保留。
- **B FPGA 步长**：重置、回绕等非正步长不参与估计；无独立时钟时缺帧未知。
- **C 分时汇总**：两条线分母不同。跨分箱的长缺口整体归开始所在分箱，绿线可能超过 100%。
- **D 接收间隔分布**：使用原始 LSL 时间戳，横轴线性显示 0–200 ms，每 1 ms 一箱，纵轴为对数计数。超过 200 ms 的间隔在统计框中单列。
- **E FPGA 步长分布**：多周期步长可提示缺帧，具体丢失环节仍需额外证据。
- **F 主机与 FPGA 时钟**：无 FPGA 时钟时不可用；时钟回绕或重置会影响整段拟合的解释。

## 图 2：Delivery delay overview

### 计算公式
**符号**
- x：FPGA 经过时间；y：主机 LSL 经过时间；b：全段拟合的主机与 FPGA 时钟速率比。
- r = y − b·x；d = (r − min(r)) × 1000 ms，以全段最快参考帧为零。
- W：FPGA 时间分窗长度，默认 60 秒。

**步骤**
1. A 显示 0–150 ms 的主体分布，每 2 ms 一箱，以全段收到的帧数为分母。
2. B 显示完整分布，纵轴为对数计数，标出 150 ms 参考线以及超过该值的帧数和比例。
3. C 按 W 分窗展示中位数和 P95，灰色阴影标出不足一窗的末段。

### 结果解读
- **A 主体分布**：查看典型延迟及集中区间。
- **B 完整分布**：查看罕见高延迟的数量与范围。
- **C 时间趋势**：定位中位数或 P95 升高的时间段。

### 质量评价标准
- **A 主体分布**：延迟是相对最快帧的额外等待，绝对延迟未知。
- **B 完整分布**：150 ms 是相对延迟的读图参考。
- **C 时间趋势**：使用统一的全段拟合和零点。没有 FPGA 时钟时无此页，存在回绕或重置时整段图标记为不可用。

## 图 3：Loss over time and per trial

### 计算公式
**符号**
- `B`：时间分箱长度，参数「时间分箱」，默认 1 min，从第一帧起算。
- `θ`：接收缺口阈值，参数「接收缺口阈值」，默认 0.15 s；接收缺口 = LSL 接收间隔 > θ。
- `lost`：FPGA 丢帧数（定义见图 1 E）。
- `a`、`b`：Topbar 分析窗口起点和终点（相对 T_TRIAL_START，默认 0.2 s 和 1.2 s）。
- `included trials`：Topbar 筛选保留的 trial；`all trial rows`：所有有开始时间的重建 trial。

**步骤**
1. 接收端损失（蓝线）= (该 bin 内开始的接收缺口总时长) ÷ (bin 时长) × 100%。
2. FPGA 损失（红线，仅有 FPGA 时钟时）= (该 bin 内开始的步的 Σ lost) ÷ (该 bin 收到帧数 + Σ lost) × 100%。
3. trial 分析窗口：[T_TRIAL_START + a, T_TRIAL_START + b)。
4. 是否触及：缺口 / 丢帧两侧相邻两帧之间的时间区间与窗口有任何重叠，就算触及。
   意思是：比 Topbar 的「窗口内缺口」判据更宽。
5. 左下：筛选前、筛选后两组都只检查分析窗口，触及比例为触及的 trial 数 ÷ 该组 trial 数 × 100%；右下（有 FPGA 时钟时）：仅展示推断缺帧数大于 0 的保留 trial，纵轴为线性整数计数，柱顶标注 trial 数。

### 结果解读
- **上方按时间影响**：分别读取接收长间隔时长占比和 FPGA 推断缺失比例。
- **左下 trial 暴露**：比较全部有起点 trial 与筛选保留 trial 的窗口是否触及接收缺口/时钟缺失。
- **右下每 trial 推断缺帧**：读取保留 trial 中缺失数量分布，定位少数高暴露窗口。

### 质量评价标准
- **上方按时间影响**：不能比较为同一种丢包率；无 FPGA 时钟仅有接收检查，不把未显示的缺失曲线当作零。
- **左下 trial 暴露**：保留组低暴露部分来自筛选；两组分母不同，不能将其解释为筛选对信号的因果改善。
- **右下每 trial 推断缺帧**：同一跨界事件可触及多个窗口，图是暴露统计；无时钟不能估计，亦无统一可接受缺帧数。

## 图 4：Supplementary Acquisition gap

每个采集缺口一张图，标题为「Acquisition gap 1」「Acquisition gap 2」…；只在有 FPGA 时钟且有缺口时出现。最多画参数「逐缺口放大图最多张数」张（默认 12，0 = 全部），
更多的缺口在说明里提示，全部缺口见表 acquisition_gaps。

### 计算公式
**符号**
- `j`：缺口前最后一帧的编号；缺口在第 j 帧和第 j+1 帧之间。
- `x`：相对第 j 帧的 FPGA 时间（ms），x = (t_fpga − t_fpga,j) × 1000。
- `y`：相对第 j 帧的主机 LSL 时间（ms）。
- `Δ`：缺口的 FPGA 时间长度（ms）；`k`：跨过的帧周期数；丢失帧数 = k − 1。
- `b`：图 1 F 的整段时钟比。
- `e`：抖动 = y − b·x（ms）。
- 显示范围：采集时间在第 j 帧前后各 200 ms 内的帧。

**步骤**
1. 取帧：FPGA 时间在 [t_fpga,j − 0.2 s, t_fpga,j + 0.2 s] 内的所有帧。
2. 坐标：x、y 都以第 j 帧为 0，所以缺口占据 x ∈ (0, Δ]（红色区域）。
3. 参考线：y = b·x（虚线），过第 j 帧。
   意思是：如果没有投递抖动，点应该落在这条线上。
4. 抖动：e = y − b·x，报告 sd、最小、最大值。
5. 标题和框：缺口两侧的 window_index（通常只差 1）、这段的 window_index 步长、显示的帧数和范围。

### 结果解读
- **缺口局部图**：每一页使用相同规则读取红带内的 FPGA 跨周期间隔、两侧帧及主机阶梯投递。

### 质量评价标准
- **缺口局部图**：缺口证明收到的序列存在时钟间断，不独立证明硬件或链路故障；局部抖动与该步缺失数应分别报告。
