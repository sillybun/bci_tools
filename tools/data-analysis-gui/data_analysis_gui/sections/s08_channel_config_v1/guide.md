# S08 · Compensation 通道筛选影响（当日 INI / Neuralinsight 日志）

通道来源支持 INI 或 Neuralinsight `.log`，顶栏可手动选择，自动查找时优先 INI。
日志取最后一次保存的 `filter.*.results_applied` 分类；结果注明时间、行号和来源文件。
两种来源都使用从 0 开始的编号，统一转换为从 1 开始的电极 ID；实际传输列顺序以 XDF 为准。
以下提到的 configs.ini 标签，同样适用于日志恢复的 good / uncertain / bad / 串扰标签。

**一句话总结：**核对当日通道配置与实际传输的映射，并在共同评估协议下比较各配置层级的信号与解码表现。

本节回答：**当天 NeuralInsight configs.ini 里的 good / uncertain / bad 标签与实际传输的 512 个通道对得上吗？
各层通道的数据质量如何？只用 good（或去掉 bad）会不会让解码更好？**
数据：按记录日期自动读取当天的通道配置 INI 或 Neuralinsight 日志，也可在顶栏手动指定；
没有通道配置 INI / LOG 的日期本节不运行。发放率与饱和度用整段记录的全部帧；ANOVA 和方向解码用 Topbar 方向队列在分析窗口内的平均发放率；
速度解码用该队列的 100 ms 速度 bin。
背景：CLI 编程时先放全部 good（升序），再放全部 uncertain，再从 bad 中随机抽取补足 512。ini 里的编号从 0 开始，这里统一换成 1 开始的电极 ID。
10-26 / 10-27 的记录传输的是电极 1..512（当时没有通道筛选），对它们只报告重叠情况，不能当作当天的编程结果。


阅读约定：以下按 subplot 的位置/标题逐项说明；重复的方向、电极、decoder 或记录面板逐个适用对应条目，双轴/色条与主面板合并解释。质量标准区分配置阈值、统计证据与描述性限制，历史数值不作为通用合格线。

## 图 1：Tiers on the array and in column order

### 计算公式
**符号**
- `j`：存储列（传输通道）编号，1–512，按采集顺序。
- `e_j`：第 j 列对应的电极 ID，1–1024。
- `good`、`uncertain`、`bad`：configs.ini 里的三份电极列表；ini 里编号从 0 开始，这里都 + 1 换成电极 ID。
- `crosstalk_channels`：ini 里的串扰电极列表（同样 + 1）。
- `tier_j`：第 j 列的层级，good / uncertain / bad / unlisted（不在任何列表中）。
- `n_good`：本记录中层级为 good 的列数。
- 层级序号：good = 0，uncertain = 1，bad = 2（unlisted 不参与顺序检查）。

**步骤**
1. 层级：tier_j = e_j 所在的列表；都不在则为 unlisted。
   意思是：用标签与本记录实际传输的电极取交集，不使用 last_programmed_channels。
2. good block first：good 列是否恰好占据第 1..n_good 列。
   意思是：CLI 是否先把 good 放在最前面。
3. good ascending：good 列的 e_j 沿列方向是否严格递增。
4. tiers in CLI order：沿列方向的层级序号是否从不减小。
   意思是：是否符合「good（升序）→ uncertain → 随机抽取的 bad」的编程顺序。
5. 图例：每层「传输数 / ini 中列出数」；× = 已传输的串扰电极。

### 结果解读
- **物理布局与默认布局**：两面板按各自坐标定位 good/uncertain/bad/unlisted 及未传输电极。
- **存储列层级条带**：按采集列顺序检查配置层级组成和是否符合约定顺序。
- **配置核对文字**：逐项读取 good 未传输、层级计数、排序及可疑电极信息。

### 质量评价标准
- **物理布局与默认布局**：配置标签是先验分类不是实测质量，未传输不等于 bad，需确认文件属于该记录日期和实际编程状态。
- **存储列层级条带**：顺序检查仅验证该约定，失败可表示配置版本不匹配而不直接证明数据损坏。
- **配置核对文字**：计数需与传输电极 ID 对齐；缺失 good、unlisted 或配置后改写时应限制按标签作结论。

## 图 2：Per-tier channel quality

### 计算公式
**符号**
- `j`：传输通道编号，1–512。
- `c_j(f)`：第 f 帧在通道 j 上的编码，0–3（3 表示 ≥3）；`N`：整段记录的帧数。
- `Δ`：每帧时长 0.020 s。
- `r_j`：整段记录的平均发放率（Hz，被上限截断）；`s_j`：饱和度（编码 ≥3 的帧所占比例）。
- `x_tj`：保留 trial t 在分析窗口 [T_TRIAL_START + 0.2 s, + 1.2 s)（Topbar 默认）内的平均发放率。
- `F`：单因素 ANOVA 统计量；`p`：对应 p 值；`df`：自由度。
- `BH-FDR q`：对全部 512 个通道的 p 值做 Benjamini–Hochberg 多重比较校正后的 q 值。
- `α`：参数「ANOVA FDR 阈值」，默认 0.05。

**步骤**
1. 平均发放率：r_j = (Σ_f c_j(f)) ÷ N ÷ Δ。
   意思是：整段记录每秒平均事件数。
2. 饱和度：s_j = (c_j(f) ≥ 3 的帧数) ÷ N。
3. 左、中图：每层每个通道一个点（对数轴，0 画在 1e−3），黑横线 = 该层中位数；横轴标签给出每层通道数 n。
4. ANOVA：对每个通道，把 x_tj 按 8 个目标方向分组，F = 组间均方 ÷ 组内均方，df = (7, trial 数 − 8)，由 F 得 p。
   意思是：检验这个通道的窗口发放率是否随方向变化。
5. 多重比较校正：对 512 个 p 值做 BH-FDR 得到 q；q < α 记为方向调制显著。
   意思是：控制「被误判为显著」的通道比例不超过 α。
6. 右图：柱高 = 该层显著通道数 ÷ 该层通道数 × 100%，柱顶标「显著数 / 层内通道数」。保留 trial < 16 时跳过。

### 结果解读
- **左侧发放率分布**：按层级比较全部传输通道的平均观测率和中位数。
- **中间饱和度分布**：比较层级中的截断程度和尾部。
- **右侧方向显著比例**：同时读每层显著数和该层有效通道分母。

### 质量评价标准
- **左侧发放率分布**：没有必须 good>bad 的生理定律；低率或标签反例需核对，不能仅据分组中位数决定剔除。
- **中间饱和度分布**：高率本来更易饱和，须结合率及 S02 的异常聚集检查；对数轴零值替代显示须读清。
- **右侧方向显著比例**：使用当前 FDR/队列；比例受样本与层级通道数影响，不能将 bad 层高于某固定百分比直接判标签失效。

## 图 3：Decoding by channel subset

只有「运行子集解码」开启且保留 trial ≥ 16 时出现。

### 计算公式
**符号**
- 子集：good；good+uncertain；all 512；bad only（少于 2 个通道的子集跳过）。
- `x_t`：保留 trial t 在分析窗口内、该子集各通道的平均发放率（特征向量）。
- `λ`：ridge 惩罚系数，参数「Ridge λ」，默认 1；实际惩罚 = n_train × λ，n_train 为训练样本数。
- block 折：按时间顺序把 block 分成 5 个连续组；每次留出一组测试，训练集去掉测试 block 范围 ±1 的 block。
- `balanced accuracy`：8 个方向各自召回率（预测正确的比例）的平均；机会水平 1/8 = 0.125。
- `v`、`v̂`、`v̄`：速度 bin 的真实速度、预测速度、真实速度均值（x、y 各算一次）。
- `R²`：决定系数。

**步骤**
1. 标准化：每个特征用训练集的均值和标准差做 z 分数。
2. 方向解码：one-hot ridge 分类器，预测方向 = 8 个输出中最大的那个；在留出 trial 上算 balanced accuracy。
   意思是：只用这组通道，能否从窗口发放率猜出目标方向。
3. 速度 bin：每个 trial 从 T_TRIAL_START + 0.2 s 起取 10 个 100 ms bin；速度 v = (bin 右端位置 − 左端位置) ÷ 0.1 s，位置由 active cursor 样本线性插值。
4. 速度特征：bin 右端往前 200 ms 内的平均发放率（需 ≥ 4 帧且缺口 ≤ 0.15 s）。
5. 速度解码：ridge 回归，同样的 block 折。
6. R² = 1 − Σ(v − v̂)² ÷ Σ(v − v̄)²，在留出 bin 上计算，x、y 两个分量取平均。
   意思是：预测能解释真实速度变化的比例；0 = 不比猜平均值好，1 = 完全一致。

### 结果解读
- **左侧方向解码**：在相同 block CV 规则下比较各通道子集的 balanced accuracy。
- **右侧速度解码**：比较相同速度协议下各子集的 R²。

### 质量评价标准
- **左侧方向解码**：对照机会水平、样本和不确定性，不将单次最高值当作配置最优；子集大小不同本身可影响性能。
- **右侧速度解码**：R²≤0 表示未优于对应均值基线；与方向结果可不同，bad 子集有预测力不证明可直接上线，在线记录还受闭环解释限制。
